Objetivo del módulo

Comprobar que el servidor acepta conexiones únicamente bajo las condiciones establecidas.

Verificar que SQL Server escucha en el puerto configurado, que el firewall permite solo el tráfico autorizado y que el usuario analítico puede consultar, pero no modificar, la información.

Fundamento teórico

¿Qué vamos a comprobar?

Lista de verificación (1 - 4)

  1. El servicio SQL Server está en ejecución.
  2. TCP/IP está habilitado.
  3. SQL Server escucha en el puerto 51433.
  4. El Firewall de Windows permite el tráfico autorizado.

Lista de verificación (5 - 7)

  1. Un equipo remoto puede establecer comunicación.
  2. El usuario analítico puede autenticarse y consultar información.
  3. El usuario NO puede ejecutar operaciones para las que no tiene permisos.

Herramientas del módulo

Con qué vas a validar.

netstat

  • Consulta las conexiones de red y los puertos en escucha.
  • Comprueba que SQL Server escucha en el puerto 51433.

Test-NetConnection

  • Comando de PowerShell que verifica la conectividad TCP entre dos equipos.
  • Se ejecuta desde el equipo cliente.

ipconfig

  • Muestra la dirección IPv4 del servidor.
  • Esa IP es la que usará el cliente para conectarse.

SSMS y T-SQL

  • Prueba la conexión remota con el login analista_upla.
  • Valida identidad, permisos y esquema de autenticación.

Actividades y evidencias

Completa cada captura en el recuadro punteado.

Actividad 1. Comprobar el puerto utilizando NETSTAT

Entorno: CMD (administrador)

netstat es una herramienta de línea de comandos que consulta las conexiones de red y los puertos en estado de escucha.

1. Abre el Símbolo del sistema de Windows (CMD) como administrador.

2. Ejecuta:

netstat -ano | findstr :51433

3. Analiza el resultado. Ejemplo ilustrativo:

TCP    0.0.0.0:51433    0.0.0.0:0    LISTENING    2456

4. Identifica el proceso asociado al puerto (reemplaza 2456 por el PID de tu equipo):

tasklist /FI "PID eq 2456"
Elemento Significado
TCP Protocolo de transporte.
0.0.0.0:51433 Escucha en todas las interfaces IPv4 disponibles.
LISTENING Puerto en estado de escucha.
2456 Identificador del proceso (PID).

Nota. Si SQL Server escucha solo en una IP específica, puede no aparecer 0.0.0.0; también puede verse la dirección IPv6 o una dirección local concreta.

Resultado esperado. El puerto TCP 51433 aparece en estado LISTENING y asociado al servicio de SQL Server.

Actividad 2. Probar la conectividad con PowerShell

Entorno: PowerShell (equipo cliente)

El comando Test-NetConnection permite verificar si existe conectividad TCP entre dos equipos.

1. Abre PowerShell en el equipo cliente.

2. Ejecuta (192.168.1.50 es la IP ilustrativa del servidor; 51433 es el puerto configurado):

Test-NetConnection -ComputerName 192.168.1.50 -Port 51433

3. Analiza el resultado. Ejemplo:

ComputerName     : 192.168.1.50
RemoteAddress    : 192.168.1.50
RemotePort       : 51433
InterfaceAlias   : Ethernet
TcpTestSucceeded : True

Conectividad TCP correcta. TcpTestSucceeded : True indica que se pudo establecer una conexión TCP con el puerto remoto.

Si aparece False, revisa: la IP del servidor · el estado del servicio SQL Server · la configuración TCP/IP · el puerto estático · las reglas del firewall · la conectividad entre ambos equipos.

Importante. Una prueba TCP exitosa no demuestra que la autenticación sea correcta. Solo verifica que existe comunicación con el puerto.

Actividad 3. Obtener la dirección IP del servidor

Entorno: CMD

1. En el equipo donde está instalado SQL Server, ejecuta: ipconfig

2. Identifica la dirección IPv4 de la interfaz de red que utilizará el cliente (ejemplo: 192.168.1.50).

3. Esta dirección se usará para conectarse desde otro equipo.

Recomendación. Para el laboratorio, el servidor debe tener una dirección IP estable, mediante una reserva DHCP o una configuración de red administrada.

Actividad 4. Conectar desde SSMS (conexión remota)

Verifica el acceso remoto utilizando el usuario creado.

1. Abre SSMS desde el equipo cliente.

2. En la ventana Connect to Server selecciona Server type: Database Engine.

3. En Server name escribe: tcp:192.168.1.50,51433

4. En Authentication selecciona SQL Server Authentication.

5. Ingresa las credenciales: Login analista_upla · Password: la definida en el laboratorio.

6. Presiona Connect.

Instancias nombradas. Al conectarse con tcp:IP,puerto no se necesita SQL Server Browser para descubrir el puerto. Si usas el nombre de la instancia sin puerto, la resolución puede requerir SQL Server Browser.

Resultado esperado. El cliente se conecta al motor usando el puerto 51433 y las credenciales de analista_upla.

Actividad 5. Validar la autenticación y los permisos

Entorno: consulta nueva (conexión remota) mediante T-SQL

Con la conexión remota establecida, abre una nueva consulta y ejecuta:

SELECT
    SUSER_SNAME() AS LoginActual,
    USER_NAME() AS UsuarioBaseDatos,
    DB_NAME() AS BaseDatosActual,
    @@SERVERNAME AS NombreServidor;
GO
Campo Resultado esperado
LoginActual analista_upla
UsuarioBaseDatos analista_upla
BaseDatosActual ProyectoAnalitico_UPLA
NombreServidor Nombre de la instancia

5A. Prueba de autorización: permisos de lectura (T-SQL)

USE ProyectoAnalitico_UPLA;
GO

SELECT
    HAS_PERMS_BY_NAME(
    DB_NAME(),
    'DATABASE',
    'SELECT'
    ) AS PermisoLectura;
GO

Resultado esperado. PermisoLectura = 1 (el usuario tiene el permiso evaluado en ese ámbito).

5B. Prueba de restricción: intentar crear una tabla (T-SQL)

USE ProyectoAnalitico_UPLA;
GO

CREATE TABLE PruebaSeguridad (
    Id INT PRIMARY KEY,
    Descripcion VARCHAR(100)
);
GO

Resultado esperado. La operación debe generar un error de permisos si el usuario solo tiene lectura. Esto demuestra que la cuenta puede consultar pero no modificar la estructura de la base de datos.

No lo "arregles". No concedas el permiso de creación solo para evitar este error: el rechazo es precisamente la evidencia de que el control de acceso funciona.

Actividad 6. Conexión desde SQL (sys.dm_exec_connections)

Con una cuenta administrativa, ejecuta la siguiente consulta en el servidor:

SELECT
    session_id,
    local_net_address AS DireccionServidor,
    local_tcp_port AS PuertoTCP,
    client_net_address AS DireccionCliente,
    net_transport AS Transporte,
    auth_scheme AS EsquemaAutenticacion
FROM sys.dm_exec_connections
WHERE session_id = @@SPID;
GO
Campo Valor esperado (conexión TCP remota)
net_transport TCP
local_tcp_port 51433
client_net_address Dirección IP del equipo cliente
auth_scheme SQL (para un login SQL)
