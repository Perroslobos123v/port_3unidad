Estrategia de respaldo periódico y recuperación ante fallos operativos

Backup completo y diferencial, BACKUP/RESTORE DATABASE y verificación de respaldos de la base de datos GradosTitulos.

iObjetivo del proyecto

Implementar una estrategia de respaldo y recuperación de GradosTitulos mediante copias completas y diferenciales, procedimientos de restauración y mecanismos de verificación, para garantizar la disponibilidad de la información ante incidentes operativos.

✖Situación problemática

La oficina de Grados y Títulos no tiene una estrategia formal de respaldo; los datos viven solo en el servidor principal y un operador eliminó por error registros de trámites y pagos sin que existiera un procedimiento de recuperación.

1.1 Análisis de la base de datos y datos críticos

GradosTitulos soporta los procesos de grados y títulos: expedientes, pagos, trabajos de investigación, evaluaciones, resoluciones, diplomas y la seguridad institucional. La información se organiza por esquemas; cada uno se clasificó según el impacto que tendría su pérdida.

EsquemaContenidoCriticidad
TramiteTrámites, pagos y trabajos de investigaciónCrítica
DocumentoResoluciones y diplomasCrítica
EvaluacionEvaluaciones, sustentaciones, juradosAlta
AcademicoPersonas, matrículas, programasAlta
CatalogoFacultades y tablas maestrasMedia
SeguridadUsuarios, roles, permisos y auditoríaCrítica

Para sustentar el inventario se puede listar las tablas por esquema con su número de filas:

T-SQL
USE GradosTitulos;
GO
SELECT s.name AS Esquema, t.name AS Tabla, SUM(p.rows) AS Filas
FROM sys.tables t
INNER JOIN sys.schemas s ON t.schema_id = s.schema_id
INNER JOIN sys.partitions p ON p.object_id = t.object_id AND p.index_id IN (0,1)
GROUP BY s.name, t.name
ORDER BY s.name, t.name;
GO

1.3 Política de respaldo

TipoFrecuenciaHorarioDestinoRetención
CompletoSemanal (domingo)02:00C:\Backups\GradosTitulos\FULL5 semanas
DiferencialDiario (lunes a sábado)02:00C:\Backups\GradosTitulos\DIFF2 semanas
Copia externaSemanalTras el completoDisco externo o recurso de red4 semanas

Justificación. El respaldo completo semanal es la base de la cadena; el diferencial diario guarda solo lo que cambió desde ese completo, por lo que es más rápido y pequeño que repetir el completo. Con esta combinación, la pérdida máxima por un error operativo es de hasta un día de trabajo y la restauración requiere solamente dos archivos: el último completo y el último diferencial. La copia externa evita que una falla del servidor se lleve también los respaldos.

Nomenclatura de los archivos

NOMBRES
GradosTitulos_FULL_AAAAMMDD_HHMM.bak   -- ejemplo: GradosTitulos_FULL_20261122_0200.bak
GradosTitulos_DIFF_AAAAMMDD_HHMM.bak   -- ejemplo: GradosTitulos_DIFF_20261123_0200.bak

La fecha y la hora dentro del nombre permiten identificar de inmediato el respaldo más reciente.

Estructura de directorios

CARPETAS
C:\Backups\
    GradosTitulos\
        FULL\   -- copias completas (retención 5 semanas)
        DIFF\   -- copias diferenciales (retención 2 semanas)
        LOG\    -- reservada para backups del log (Proyectos 3 y 4)
    Lab\        -- archivos de la base de laboratorio y pruebas

1.4 Criterios de verificación y límites de la estrategia

  • Todo respaldo se genera con CHECKSUM y se comprueba de inmediato con RESTORE VERIFYONLY.
  • Las restauraciones de prueba se hacen en GradosTitulos_Lab para no tocar la base original.
  • El diferencial depende del último completo: si se hace un nuevo completo sin __COPY_ONLY__, el diferencial anterior deja de ser válido para ese completo.
  • Esta estrategia permite volver al último respaldo, no a un instante exacto; para eso se necesita el modelo FULL y backups del log (Proyecto 3).
2

Script SQL de backups completos y diferenciales

T-SQL

!Importante

No uses WITH INIT ni FORMAT sobre archivos que necesites conservar. El diferencial se calcula desde el último completo, por eso siempre debe existir un completo previo.

T-SQL
-- Estructura de carpetas de respaldo
EXEC master.dbo.xp_create_subdir N'C:\Backups\GradosTitulos\FULL';
EXEC master.dbo.xp_create_subdir N'C:\Backups\GradosTitulos\DIFF';
EXEC master.dbo.xp_create_subdir N'C:\Backups\GradosTitulos\LOG';
EXEC master.dbo.xp_create_subdir N'C:\Backups\Lab';
GO
-- Backup COMPLETO con verificación
DECLARE @f NVARCHAR(20) = FORMAT(GETDATE(),'yyyyMMdd_HHmm');
DECLARE @r NVARCHAR(300) = N'C:\Backups\GradosTitulos\FULL\GradosTitulos_FULL_' + @f + N'.bak';
BACKUP DATABASE GradosTitulos
TO DISK = @r
WITH CHECKSUM, COMPRESSION, STATS = 10, NAME = N'GradosTitulos - Completo';
RESTORE VERIFYONLY FROM DISK = @r WITH CHECKSUM;
GO
-- Backup DIFERENCIAL (requiere un completo previo)
DECLARE @f NVARCHAR(20) = FORMAT(GETDATE(),'yyyyMMdd_HHmm');
DECLARE @r NVARCHAR(300) = N'C:\Backups\GradosTitulos\DIFF\GradosTitulos_DIFF_' + @f + N'.bak';
BACKUP DATABASE GradosTitulos
TO DISK = @r
WITH DIFFERENTIAL, CHECKSUM, COMPRESSION, STATS = 10, NAME = N'GradosTitulos - Diferencial';
RESTORE VERIFYONLY FROM DISK = @r WITH CHECKSUM;
GO

Opciones utilizadas

OpciónPara qué sirve
CHECKSUMCalcula sumas de verificación para detectar páginas dañadas al respaldar y al verificar.
COMPRESSIONReduce el tamaño del archivo .bak y el tiempo de escritura en disco.
STATS = 10Muestra el avance cada 10 %; sirve como evidencia del mensaje de éxito.
NAMEEtiqueta interna del respaldo; ayuda a identificarlo en el historial de msdb.
DIFFERENTIALRespalda solo los cambios hechos desde el último completo.
RESTORE VERIFYONLYComprueba que el archivo es legible y está completo, sin restaurarlo.
3

Script SQL de restauración

T-SQL

✔Laboratorio seguro

La restauración se hace sobre GradosTitulos_Lab para no tocar la base original. Antes de ejecutar, cambia AAAAMMDD_HHMM por la fecha de tus archivos y reemplaza <LogicalNameDatos> y <LogicalNameLog> por los nombres que devuelva FILELISTONLY.

T-SQL
-- Obtener los nombres lógicos para WITH MOVE
RESTORE FILELISTONLY
FROM DISK = N'C:\Backups\GradosTitulos\FULL\GradosTitulos_FULL_AAAAMMDD_HHMM.bak';
GO
USE master;
GO
-- 1) Completo: la base queda en restauración
RESTORE DATABASE GradosTitulos_Lab
FROM DISK = N'C:\Backups\GradosTitulos\FULL\GradosTitulos_FULL_AAAAMMDD_HHMM.bak'
WITH MOVE N'<LogicalNameDatos>' TO N'C:\Backups\Lab\GradosTitulos_Lab.mdf',
     MOVE N'<LogicalNameLog>'   TO N'C:\Backups\Lab\GradosTitulos_Lab_log.ldf',
     NORECOVERY, REPLACE, STATS = 10;
-- 2) Diferencial: finaliza la secuencia
RESTORE DATABASE GradosTitulos_Lab
FROM DISK = N'C:\Backups\GradosTitulos\DIFF\GradosTitulos_DIFF_AAAAMMDD_HHMM.bak'
WITH RECOVERY, STATS = 10;
GO

Cómo funciona la secuencia. El completo se restaura con NORECOVERY: la base queda en estado «restaurando» y todavía no se puede usar, porque falta aplicar los cambios posteriores. El diferencial se restaura con RECOVERY, que cierra la cadena y deja la base ONLINE. Si se usara RECOVERY en el completo, ya no se podría aplicar el diferencial.

RESULTADO

Con completo semanal y diferencial diario, la pérdida máxima por error operativo es de hasta un día de trabajo, y la restauración requiere solo dos archivos.

Conclusiones

  • Se definió una política formal de respaldo (completo semanal + diferencial diario) con destino, nomenclatura y retención, que no existía en la oficina de Grados y Títulos.
  • Los respaldos se verifican al momento de crearlos; un respaldo sin verificar no se considera válido.
  • La restauración controlada en GradosTitulos_Lab permite demostrar la recuperación sin riesgo para la base de producción.
  • Para recuperar a un instante exacto, o reducir la pérdida a minutos, se requiere el modelo FULL con backups del log (Proyecto 3).
