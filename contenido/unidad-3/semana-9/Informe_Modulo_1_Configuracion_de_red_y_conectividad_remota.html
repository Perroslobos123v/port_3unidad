ACTIVIDAD1

Identificar la instancia de SQL Server

SQL Server

iObjetivo

Identificar el nombre de la instancia y comprobar que el servicio del motor esté en ejecución.

Procedimiento
  1. Presiona Windows + R.
  2. Escribe services.msc y presiona Enter.
  3. Busca el servicio de SQL Server e identifica el nombre de tu instancia.
  4. Comprueba que su estado sea En ejecución.
ServicioDescripción
SQL Server (MSSQLSERVER)Instancia predeterminada
SQL Server (SQLEXPRESS)Instancia denominada
SQL Server AgentProgramación de tareas
Explicación técnica

El nombre del servicio indica el tipo de instancia: la predeterminada se conecta solo con el nombre del equipo y la denominada, con equipo\instancia. Si el motor no está en ejecución, ninguna de las configuraciones siguientes servirá.

✓Resultado esperado

Instancia identificada y motor activo.

✎Respuesta para el informe

Se verificó el servicio de Microsoft SQL Server mediante la herramienta Servicios de Windows. Se identificó la instancia instalada y se comprobó que su estado fuera En ejecución, garantizando que el motor de base de datos estuviera disponible.

ACTIVIDAD2

Habilitar el protocolo TCP/IP

SQL Server

iObjetivo

Habilitar TCP/IP para permitir la comunicación de SQL Server mediante conexiones de red.

Procedimiento
  1. Presiona Windows + R y ejecuta el administrador de configuración de tu versión: SQLServerManager15.msc (2019), SQLServerManager16.msc (2022) o SQLServerManager17.msc (2025).
  2. Abre SQL Server Network Configuration.
  3. Selecciona Protocols for MSSQLSERVER o Protocols for SQLEXPRESS.
  4. Haz clic derecho sobre TCP/IP y elige Enable.
  5. Comprueba que aparezca como Enabled.
Explicación técnica

TCP/IP es el protocolo que usan las conexiones por red. Con Shared Memory solo se conectan programas del mismo equipo, por eso TCP/IP debe estar en Enabled.

✓Resultado esperado

TCP/IP habilitado para recibir conexiones de red.

✎Respuesta para el informe

Se habilitó el protocolo TCP/IP desde SQL Server Configuration Manager, permitiendo que el motor de base de datos pueda recibir conexiones mediante el protocolo de comunicación TCP/IP.

ACTIVIDAD3

Configurar un puerto TCP estático

SQL Server

iObjetivo

Configurar el puerto TCP 51433 para que SQL Server utilice un puerto fijo en las conexiones entrantes.

Procedimiento
  1. En Configuration Manager, entra en Protocols de tu instancia.
  2. Haz doble clic en TCP/IP y abre la pestaña IP Addresses.
  3. Desplázate hasta la sección IPAll.
  4. Deja TCP Dynamic Ports completamente vacío.
  5. En TCP Port escribe 51433.
  6. Presiona Apply y luego OK.
  7. En SQL Server Services, clic derecho sobre tu instancia y Restart.
ParámetroConfiguración
TCP Dynamic PortsVacío
TCP Port51433
Explicación técnica

Con puertos dinámicos, SQL Server elige uno distinto en cada inicio y no se puede abrir en el firewall con una regla fija. Un puerto estático hace la conexión predecible.

!Importante

El reinicio es necesario para aplicar el cambio. Revisa también que ninguna IP individual tenga valores que contradigan el puerto.

✓Resultado esperado

SQL Server escucha en el puerto TCP 51433.

✎Respuesta para el informe

Se configuró un puerto TCP estático con el valor 51433 en las propiedades del protocolo TCP/IP. Asimismo, se deshabilitó la asignación dinámica de puertos y se reinició el servicio de SQL Server para aplicar los cambios.

ACTIVIDAD4

Habilitar las conexiones remotas desde SSMS

SQL Server

iObjetivo

Permitir que otros equipos puedan conectarse al servidor mediante una conexión de red.

Procedimiento
  1. Abre SQL Server Management Studio (SSMS).
  2. Conéctate a tu instancia con autenticación de Windows.
  3. En el Explorador de objetos, clic derecho sobre el servidor y Properties.
  4. Entra en Connections.
  5. Activa Allow remote connections to this server.
  6. Presiona OK.
Explicación técnica

Esta opción controla si el servidor acepta conexiones desde otros equipos. Por sí sola no basta: también deben estar habilitados TCP/IP y la regla del firewall.

✓Resultado esperado

El servidor permite conexiones remotas, siempre que TCP/IP y el firewall estén configurados.

✎Respuesta para el informe

Se habilitaron las conexiones remotas desde las propiedades del servidor en SQL Server Management Studio. Esta configuración permite que otros equipos puedan establecer comunicación con el motor de base de datos, siempre que cumplan las condiciones de conectividad y seguridad establecidas.

ACTIVIDAD5

Configurar el Firewall de Windows

SQL Server

iObjetivo

Crear una regla de entrada que permita el tráfico TCP por el puerto 51433.

Procedimiento
  1. Abre Firewall de Windows Defender con seguridad avanzada y entra en Reglas de entrada.
  2. En el panel derecho, elige Nueva regla, tipo Puerto, y presiona Siguiente.
  3. Selecciona TCP y Puertos locales específicos; escribe 51433.
  4. Elige Permitir la conexión.
  5. Marca solo el perfil de red del laboratorio, preferentemente Privado.
  6. Asigna el nombre SQL Server TCP 51433 - UPLA y finaliza.
Restricción por dirección IP (opcional)
  1. Abre las Properties de la regla creada y entra en Scope.
  2. En Remote IP address elige These IP addresses.
  3. Agrega las direcciones IP reales de los equipos autorizados.

!Ojo

Las direcciones 192.168.1.100 y 192.168.1.101 del PDF son ejemplos; no las copies si no corresponden a tu red.

Explicación técnica

El firewall bloquea por defecto el tráfico entrante. Abrir solo el puerto 51433, en el perfil adecuado y para IP concretas, reduce la superficie de ataque.

✓Resultado esperado

El firewall permite TCP 51433 únicamente desde los equipos autorizados, si se aplica la restricción de IP.

✎Respuesta para el informe

Se creó una regla de entrada en el Firewall de Windows Defender para permitir el tráfico TCP mediante el puerto 51433. Además, se estableció la posibilidad de restringir las conexiones a determinadas direcciones IP, mejorando el control de acceso al servidor SQL Server.
