iObjetivo del proyecto

Diseñar e implementar un plan integral de continuidad operativa y recuperación ante desastres de GradosTitulos, con respaldo completo, diferencial y de log, políticas de retención, restauración, recuperación punto en el tiempo y pruebas de contingencia, para garantizar disponibilidad, integridad y recuperación de la información.

✖Situación problemática

GradosTitulos concentra datos académicos, administrativos y de seguridad (usuarios, roles, permisos y auditoría). La institución no tiene un plan ante pérdida total del servidor, corrupción de archivos, eliminación accidental, errores de configuración o respaldos comprometidos.

RPO: pérdida de datos tolerable, medida en tiempo. RTO: tiempo máximo de interrupción aceptable. Con logs cada 15 minutos se cumple el RPO de las tablas críticas.

!Observación sobre el RTO

La suma de los tiempos máximos planificados (165 min = 2 h 45 min) supera el RTO crítico de 2 h. En el simulacro se miden los tiempos reales (Entregable 14); si no se cumple el objetivo, se proponen mejoras en «Lecciones aprendidas»: preautorizar la selección de la cadena, solapar las fases de comunicación y contención, y dejar el script de restauración listo para ejecutar.

El servidor principal escribe sus respaldos en un disco distinto al de datos; de allí se copian a un destino externo. Cada archivo se verifica y su resultado se supervisa mediante la bitácora; ante una contingencia, los respaldos se restauran en un servidor o entorno alterno.

Scripts de backup: completo, diferencial, log y sistema

T-SQL

!Antes de ejecutar los backups del log

La base debe estar en modelo FULL y debe existir un respaldo completo normal previo (no COPY_ONLY); de lo contrario BACKUP LOG falla.

T-SQL
ALTER DATABASE GradosTitulos SET RECOVERY FULL;
GO
-- Backup COMPLETO con verificación
DECLARE @f NVARCHAR(20) = FORMAT(GETDATE(),'yyyyMMdd_HHmm');
DECLARE @r NVARCHAR(300) = N'C:\Backups\GradosTitulos\FULL\GradosTitulos_FULL_' + @f + N'.bak';
BACKUP DATABASE GradosTitulos
TO DISK = @r
WITH CHECKSUM, COMPRESSION, STATS = 10, NAME = N'GradosTitulos - Completo';
RESTORE VERIFYONLY FROM DISK = @r WITH CHECKSUM;
GO
-- Backup DIFERENCIAL (requiere un completo previo)
DECLARE @f NVARCHAR(20) = FORMAT(GETDATE(),'yyyyMMdd_HHmm');
DECLARE @r NVARCHAR(300) = N'C:\Backups\GradosTitulos\DIFF\GradosTitulos_DIFF_' + @f + N'.bak';
BACKUP DATABASE GradosTitulos
TO DISK = @r
WITH DIFFERENTIAL, CHECKSUM, COMPRESSION, STATS = 10, NAME = N'GradosTitulos - Diferencial';
RESTORE VERIFYONLY FROM DISK = @r WITH CHECKSUM;
GO
-- Backup del LOG (modelo FULL) cada 15 minutos
DECLARE @f NVARCHAR(20) = FORMAT(GETDATE(),'yyyyMMdd_HHmm');
DECLARE @r NVARCHAR(300) = N'C:\Backups\GradosTitulos\LOG\GradosTitulos_LOG_' + @f + N'.trn';
BACKUP LOG GradosTitulos TO DISK = @r WITH CHECKSUM, COMPRESSION, STATS = 10;
RESTORE VERIFYONLY FROM DISK = @r WITH CHECKSUM;
GO
-- Bases del sistema: logins, trabajos y configuración
EXEC master.dbo.xp_create_subdir N'C:\Backups\Sistema';
DECLARE @f NVARCHAR(20) = FORMAT(GETDATE(),'yyyyMMdd_HHmm');
DECLARE @m NVARCHAR(300) = N'C:\Backups\Sistema\master_' + @f + N'.bak';
DECLARE @d NVARCHAR(300) = N'C:\Backups\Sistema\msdb_' + @f + N'.bak';
BACKUP DATABASE master TO DISK = @m WITH CHECKSUM, COMPRESSION;
BACKUP DATABASE msdb TO DISK = @d WITH CHECKSUM, COMPRESSION;
GO

Automatización, supervisión y mantenimiento

PROCEDIMIENTO
TareaProgramaciónHerramienta
Backup completoDomingo 02:00Trabajo del Agente SQL o Programador de tareas
Backup diferencialLunes a sábado 02:00Trabajo del Agente SQL o Programador de tareas
Backup del logCada 15 minutosTrabajo del Agente SQL (freq_subday_type = 4, interval 15)
Verificación diaria06:00usp_VerificarBackups (ver Proyecto 2)
RetenciónDomingo 05:00usp_Retencion con guarda de seguridad

Los trabajos del completo y del diferencial se crean como en el Proyecto 2. El del log usa el mismo procedimiento usp_Backup con el tipo LOG y una programación diaria repetida cada 15 minutos:

SQL AGENT
USE msdb;
GO
EXEC dbo.sp_add_job @job_name = N'Backup_LOG_GradosTitulos';
EXEC dbo.sp_add_jobstep @job_name = N'Backup_LOG_GradosTitulos', @step_name = N'LOG',
    @subsystem = N'TSQL', @database_name = N'DBA_Admin',
    @command = N'EXEC dbo.usp_Backup @Tipo = ''LOG'';';
EXEC dbo.sp_add_jobschedule @job_name = N'Backup_LOG_GradosTitulos', @name = N'Cada 15 min',
    @freq_type = 4, @freq_interval = 1, @freq_subday_type = 4, @freq_subday_interval = 15,
    @active_start_time = 000000;
EXEC dbo.sp_add_jobserver @job_name = N'Backup_LOG_GradosTitulos';
GO
-- Supervisión: último respaldo de cada tipo
SELECT d.name AS BaseDatos,
  MAX(CASE WHEN b.type='D' THEN b.backup_finish_date END) AS UltimoCompleto,
  MAX(CASE WHEN b.type='I' THEN b.backup_finish_date END) AS UltimoDiferencial,
  MAX(CASE WHEN b.type='L' THEN b.backup_finish_date END) AS UltimoLog
FROM sys.databases d
LEFT JOIN msdb.dbo.backupset b ON b.database_name = d.name
WHERE d.name IN ('GradosTitulos','master','msdb')
GROUP BY d.name;
GO

-- 1) Completo: la base queda en restauración

RESULTADO

El plan permite recuperar GradosTitulos tras una pérdida total, una corrupción o un error humano, con pérdida máxima de 15 minutos en las tablas críticas y un procedimiento documentado y probado.

Conclusiones

  • La combinación de completo, diferencial y log, con copia externa, cubre los riesgos de hardware, error humano, corrupción y ransomware.
  • Los objetivos RPO y RTO por esquema orientan la frecuencia de respaldo y la prioridad de recuperación.
  • Las pruebas periódicas de restauración y la verificación diaria dan confianza real en que los respaldos sirven.
  • Recuperar el esquema Seguridad y reparar usuarios huérfanos es indispensable para reabrir el servicio en un servidor alterno.
